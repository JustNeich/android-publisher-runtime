# Codex: развернуть готовый Publisher без плагина

Выполняй техническую работу сам; человеку — короткое пояснение и одно необходимое действие. Не предлагай карточки, каталоги, plugin add, prepare-catalog или регистрацию MCP в desktop. Встроенный job-scoped MCP запускается самой службой; его не надо заменять внешним инструментом. Не переписывай движок на компьютере получателя.

## Получение и сохранность установки

1. Проверь macOS и Git командой `git --version`. Если Git отсутствует, предложи штатное окно `xcode-select --install`, дождись завершения человеком и повтори проверку. Не устанавливай Homebrew или GitHub connector ради клонирования. Публичный HTTPS Git читается без аккаунта и ключей.
2. Клонируй `https://github.com/JustNeich/android-publisher-runtime.git` в постоянную папку проекта получателя. Если клон уже существует, проверь origin и локальные изменения; не делай reset/clean. Для получения новой версии используй отдельный чистый checkout. Запиши commit и версию; прочитай AGENTS.md.
3. До установки проверь существующий `~/Library/Application Support/AndroidPublisher/runtime/active.json` без вывода секретов. Если существует, возьми оттуда app/data/python и вызови прежний `bin/publisher status`; сохрани installation ID, очередь, текущую паузу и Keychain service. При другом явном ANDROID_PUBLISHER_RUNTIME/DATA используй те же пути. Не создавай новую identity. Не запускай остановленную установку. Существующий исправный runtime можно оставить для настройки; смена версии проходит отдельным update/rollback по operations.md, а не молчаливым install.sh поверх него.
4. Проверь все пути и SHA-256 из PACKAGE.sha256.json (без абсолютных путей, `..` и symlink). Установщик повторяет проверку состава. На чистом Mac исполни `/bin/sh /absolute/checkout/install.sh`. Он скачивает Python 3.12.13 и Codex CLI 0.144.1 по проверяемым SHA-256, ставит offline wheels по requirements.lock и копирует runtime в Application Support. Общий CLI и config/cache Codex не изменяются. Плагин не нужен. Сам install.sh не запускает службу, Telegram или очередь.
5. В дальнейшем используй `bin/publisher` активного app из active.json. Исходный checkout не должен владеть состоянием; его удаление не должно ломать службу. Сохрани у получателя путь проекта для новых чатов: его AGENTS.md ведёт к этим инструкциям, status и журналу развёртывания. Не регистрируй глобальные навыки.

## Личные входы

Вызови `bin/publisher init`. Если закреплённый CLI ещё не вошёл через ChatGPT, подготовь его `codex login`; человек входит сам. Не заменяй подписку API-ключом. Затем `bin/publisher telegram-login`: собственные номер/коды/2FA и API-доступ пользователя получаются в защищённых окнах, сессия хранится в Keychain этой установки. Не заимствуй Assistant/Desktop session.

`bin/publisher private-pin --phone PHONE` открывает скрытое поле для PIN. Никогда не помещай PIN в команду, manifest или переписку. `keychain-authorize` позволяет человеку подтвердить системные права для закреплённого Python, затем `background-preflight` проверяет доступ именно из временного LaunchAgent. Разрешение Keychain и входы нельзя заменить знанием PIN.

## Телефон: Type-C → Wi-Fi

Сначала `bin/publisher prepare-adb`. До USB debugging агент не управляет телефоном через ADB: проведи человека по включению developer options и USB debugging на его модели, попроси USB Allow для этого Mac. При необходимости разблокирование/нажатия выполняет человек. Проверь `adb devices -l`; если телефонов несколько, установи соответствие по физическому serial.

`bin/publisher usb-setup --phone PHONE --serial SERIAL` устанавливает закреплённый Android-коннектор, сохраняет другие Accessibility-службы, настраивает автозапуск и Wi-Fi ADB. Не сбрасывай существующий bearer без исследования разрешённого прежнего контура. Настройки Android, требующие системного подтверждения, подтверждает человек.

Попроси **физически вынуть Type-C**. Только после его подтверждения выполни `verify-phone --phone PHONE`, затем `probe-phone --phone PHONE`: свежий экран Studio, текущий канал, завершение с погашенным экраном. Проба не публикует. Отдельно установи действительный UC ID выбранного канала через свежий Studio/YouTube readback, а не имя/alias. Проверь Internet телефона. Смена IP допускает поиск только с проверкой того же serial. После reboot могут потребоваться первое разблокирование и повторный USB tcpip; не обещай безусловного восстановления без кабеля.

## Связка и правила

Спроси только недостающее: какой телефон/YouTube-канал, какая Telegram-группа и топик, timezone и часы, правила метаданных/аудитории. Если группа ещё не существует, согласуй создание. Не назначай свои каналы. Подтверди действующие правила: каждый MP4 получает Да/Нет; Да резервирует следующий слот и запускает предварительную загрузку, а не немедленный Public. Автоодобрение не включай молча.

Создай либо переиспользуй один согласованный бот (`provision-bot`) и существующую форумную группу (`configure-group`). Если согласована новая группа — `provision-group --channel CHANNEL --title TITLE`. Codex делает технические шаги, человек подтверждает необходимые личные входы. После неизвестного результата сначала сверяй журнал/ресурс, не создавай дубль.

Составь приватный несекретный manifest только из проверенных/согласованных значений:

```json
{"phone":"PHONE","channel":"CHANNEL","name":"Название канала","youtube_id":"UC_exact_22_characters_here","chat_id":-1000000000123,"publication_topic":10,"general_topic":1,"timezone":"Europe/Moscow","times":["19:00"],"bot_username":"agreed_bot","bot_name":"Android Publisher","defaults":{"description":"","tags":[],"audience":"not_kids"}}
```

Это пример формы, не готовые defaults. Audience, timezone, часы и IDs нельзя угадывать. Используй `deploy --manifest /private/path/manifest.json`; шаги сохраняются и повторяются идемпотентно. Deploy устанавливает LaunchAgent, но оставляет очередь **на паузе** и состояние pending_live_acceptance. Исторические MP4 предложи через import-preview; импортируй только выбранные, с прежним Да/Нет.

## Проверка и эксплуатация

Проверь status, doctor, background-preflight, основной/health heartbeat и launchd под установленным runtime. Успех doctor не заменяет полезный результат. Только после согласования конкретных пробных MP4/слотов и выпуска можно resume. Не публикуй случайный ролик ради проверки связи.

Проверяй человеческий и ботский MP4, Да/Нет и повтор кнопки, Scheduled в Studio, перенос, отмену→Private, согласованный Public и зрительский URL. При неизвестном эффекте — readback по прежнему ролику до повторной загрузки. Снятый кабель и исходно погашенный экран — обязательные условия телефонной проверки. С разрешения пользователя проверь перезапуск его службы/телефона и смену IP, сохранность очереди, update/rollback; не отключай чужой VPN и не перезагружай Mac без поручения.

Фиксируй `acceptance-report` локально без секретов. Полная продуктовая приёмка требует двух физических телефонов; настройка одного не доказывает второй. Пока нет фактов — pending_live_acceptance. После закрытия чата работает служба; Mac должен оставаться включённым, не спящим, с вошедшим пользователем macOS. При sleep/offline события дочитываются по сохранённым курсорам, но выключенный Mac не выполняет задачи.
